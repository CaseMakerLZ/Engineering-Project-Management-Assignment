## 4. 今日异常处理体系现状

当前 `exception` 包新增了：

```text
exception/
├── BaseException.java
├── GlobalExceptionHandler.java
├── AgentServiceException/
│   └── AgentServiceException.java
└── 此异常体系设计参考.txt
```

### 4.1 `BaseException`

作为自定义业务异常基类，当前包含：

- 数字错误码；
- 异常消息；
- 原始异常原因 `cause`。

支持两种场景：

```text
业务代码主动抛出异常
底层异常包装成业务异常后重新抛出
```

### 4.2 `AgentServiceException`

当前用于表示 Python Agent Service 相关异常，并定义了三个状态值：

```text
503：Python 服务不可用
404：Agent Run 不存在
504：Python 调用超时
```

### 4.3 `GlobalExceptionHandler`

当前已经具备：

- 自定义 `BaseException` 处理；
- 兜底 `Exception` 处理；
- 异常日志记录；
- 统一返回 `Result`。

## 5. 当前异常体系存在的问题

### 5.1 `PythonAgentClient` 尚未接入异常转换

当前 `PythonAgentClient` 仍然直接调用：

```java
retrieve().body(...)
```

尚未捕获并转换以下异常：

- Python 服务无法连接；
- 连接超时；
- 读取超时；
- Python 返回 404；
- Python 返回 401；
- Python 返回 500。

因此当前定义的 `AgentServiceException` 还没有真正进入调用链路。

目标流程应为：

```text
RestClient 异常
        ↓
PythonAgentClient 捕获
        ↓
转换为 AgentServiceException
        ↓
GlobalExceptionHandler
        ↓
统一 HTTP 状态和 JSON 响应
```

### 5.2 异常错误码没有真正返回

`BaseException` 保存了 `code`，但 `GlobalExceptionHandler` 当前调用：

```java
Result.error(ex.getMessage())
```

而 `Result.error()` 会固定设置：

```text
code = 0
```

所以 `503`、`404`、`504` 当前不会传递给前端。

后续需要明确区分：

```text
HTTP 状态码
业务错误码
```

不建议长期把二者混用。

### 5.3 自定义异常没有映射 HTTP 状态码

`GlobalExceptionHandler` 处理 `BaseException` 时，当前没有设置 HTTP 状态码，也没有返回 `ResponseEntity`。

因此可能出现：

```text
HTTP 状态码：200
JSON code：0
```

更合理的目标是：

```text
Python 服务不可用：HTTP 503
Agent Run 不存在：HTTP 404
调用超时：HTTP 504
```

### 5.4 参数校验异常尚未统一处理

当前请求 DTO 已使用：

```java
@NotBlank
@Size
```

但 `GlobalExceptionHandler` 还没有处理参数校验异常，例如：

- `MethodArgumentNotValidException`；
- `HandlerMethodValidationException`。

参数校验失败时，当前可能返回 Spring 默认错误格式，而不是统一的 `Result` 格式。

### 5.5 兜底异常消息过于具体

当前兜底处理器对所有未知异常都返回：

```text
Python Agent Service暂时不可用
```

这会把 Java 内部错误、数据库错误、程序 Bug 等全部误报成 Python 服务不可用。

后续应该让：

```text
AgentServiceException
    → Python 服务相关错误

其他未识别 Exception
    → 通用系统错误
```

### 5.6 命名需要修正

当前常量存在拼写问题：

```text
AGENT_SERVICE_UNAVILIBLE
AGENT_RUN_NOT_FOUNDED
```

建议修正为：

```text
AGENT_SERVICE_UNAVAILABLE
AGENT_RUN_NOT_FOUND
```

## 6. 下一步异常处理计划

建议按以下顺序推进：

```text
1. 明确 HTTP 状态码与业务错误码的关系
2. 在 PythonAgentClient 捕获 RestClient 异常
3. 将连接失败、超时、404、5xx 转为 AgentServiceException
4. 让 GlobalExceptionHandler 返回正确 HTTP 状态码
5. 增加参数校验异常处理
6. 统一兜底异常响应
7. 为异常映射增加测试
```

第一条最重要的验证链路：

```text
关闭 Python Agent Service
        ↓
Java 调用接口
        ↓
PythonAgentClient 捕获连接异常
        ↓
转换为 AgentServiceException(503)
        ↓
GlobalExceptionHandler
        ↓
HTTP 503 + 统一 JSON 响应
```
