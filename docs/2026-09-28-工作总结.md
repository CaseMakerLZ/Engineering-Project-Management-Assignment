## 2. HTTP 状态码与业务码的分工

一次错误响应现在被明确拆成两个层次。

例如 Python Agent Service 不可用时：

```http
HTTP/1.1 503 Service Unavailable
```

```json
{
  "code": 40001,
  "msg": "Agent 服务暂不可用",
  "data": null
}
```

其中：

- `503` 是 HTTP 状态码，由 `ResponseEntity` 或异常处理器设置；
- `40001` 是项目业务错误码，由 `Result` 返回；
- `msg` 是错误描述；
- `data` 在失败时通常为 `null`。

不再使用同一个数字同时表示 HTTP 状态码和业务错误码。

## 3. ErrorCode 设计

新增并完善了 `ErrorCode` 枚举，使每个错误同时包含：

```text
业务码
默认消息
HTTP 状态码
```

当前主要错误码如下：

| 枚举 | 业务码 | HTTP 状态 | 含义 |
|---|---:|---:|---|
| `SUCCESS` | `0` | `200` | 成功 |
| `INVALID_ARGUMENT` | `10001` | `400` | 请求参数不合法 |
| `USER_NOT_FOUND` | `20001` | `404` | 用户不存在 |
| `PASSWORD_ERROR` | `20002` | `401` | 密码错误 |
| `AGENT_RUN_NOT_FOUND` | `30001` | `404` | Agent Run 不存在 |
| `AGENT_RUN_STATE_CONFLICT` | `30002` | `409` | Agent Run 状态不允许当前操作 |
| `AGENT_SERVICE_UNAVAILABLE` | `40001` | `503` | Python Agent Service 不可用 |
| `AGENT_SERVICE_TIMEOUT` | `40002` | `504` | Python Agent Service 调用超时 |
| `AGENT_SERVICE_AUTH_FAILED` | `40003` | `502` | Java 与 Python 服务鉴权失败 |
| `AGENT_SERVICE_RESPONSE_ERROR` | `40004` | `502` | Python 服务返回异常 |
| `INTERNAL_SERVER_ERROR` | `90001` | `500` | Java 内部系统错误 |

业务码分段暂定为：

```text
0             成功
10000-19999   通用请求错误
20000-29999   用户与权限
30000-39999   Agent 任务
40000-49999   Python Agent Service 通信
50000-59999   项目与会话
90000-99999   系统错误
```

## 4. Result.java 调整

`Result` 当前统一约定为：

```json
{
  "code": 0,
  "msg": "success",
  "data": {}
}
```

成功：

```java
Result.success(data)
```

错误：

```java
Result.error(errorCode, message)
```

当前实际方法为：

```java
Result.error(int code, String msg)
```

`Result` 只负责 JSON 响应体，不直接管理 HTTP 状态码。

## 5. BaseException 设计

当前 `BaseException` 持有：

```java
private final ErrorCode errorCode;
```

支持以下使用方式：

```java
throw new BaseException(ErrorCode.AGENT_RUN_NOT_FOUND);
```

```java
throw new BaseException(ErrorCode.AGENT_SERVICE_TIMEOUT, cause);
```

```java
throw new BaseException(
    ErrorCode.INVALID_ARGUMENT,
    "自定义参数错误提示"
);
```

异常中的 `ErrorCode` 能同时提供：

```text
业务码
默认消息
HTTP 状态码
```

## 6. 移除 AgentServiceException

经过讨论，当前阶段不再保留：

```text
AgentServiceException
```

原因是：

```text
异常类型和错误分类重复表达
```

当前直接使用：

```java
BaseException + ErrorCode
```

例如：

```java
throw new BaseException(ErrorCode.AGENT_SERVICE_UNAVAILABLE, cause);
```

如果未来某个领域异常需要额外字段或特殊行为，再考虑建立专门的异常子类。

## 7. GlobalExceptionHandler 调整

此前异常处理器只返回 `Result`，容易导致错误响应仍然使用 HTTP 200。

现在自定义异常处理器返回：

```java
ResponseEntity<Result<Void>>
```

处理流程变为：

```text
BaseException
    ↓
读取 ErrorCode
    ↓
读取 HTTP 状态码和业务码
    ↓
ResponseEntity.status(...)
    ↓
Result.error(...)
```

例如：

```text
BaseException(ErrorCode.AGENT_SERVICE_UNAVAILABLE)
        ↓
HTTP 503
        ↓
JSON code = 40001
```

同时补充了以下异常处理：

- `MethodArgumentNotValidException`：`@Valid` 请求体校验失败；
- `HandlerMethodValidationException`：方法参数校验失败；
- `HttpMessageNotReadableException`：请求体不是合法 JSON 或字段无法解析；
- `Exception`：统一系统错误兜底。

参数校验错误统一返回：

```text
HTTP 400
业务码 10001
```

系统未知异常统一返回：

```text
HTTP 500
业务码 90001
```

同时不再把所有未知异常错误地描述成 Python Agent Service 不可用。

## 8. PythonAgentClient 异常转换

`PythonAgentClient` 现在对所有 Python HTTP 调用统一包装，并将底层异常转换为 `BaseException`。

调用结构：

```text
RestClient
    ↓
PythonAgentClient
    ↓ 捕获异常
BaseException(ErrorCode)
    ↓
GlobalExceptionHandler
    ↓
HTTP 状态码 + 业务码 + JSON
```

当前映射关系：

| Python 调用结果 | Java HTTP | Java 业务码 |
|---|---:|---:|
| 连接失败 | `503` | `40001` |
| 连接/读取超时 | `504` | `40002` |
| Python 返回 `401/403` | `502` | `40003` |
| Python 返回 `404` | `404` | `30001` |
| Python 返回 `409` | `409` | `30002` |
| Python 返回 `422` | `400` | `10001` |
| Python 返回 `503` | `503` | `40001` |
| Python 返回其他错误状态 | `502` | `40004` |
| 响应无法解析 | `502` | `40004` |

Python 返回 `401/403` 时，Java 不直接把它当成网站用户认证失败，而是视为 Java 与 Python 内部服务之间的配置或鉴权问题，因此对外转换为 `502`。

## 9. 创建任务接口的 HTTP 202

Java 的：

```text
POST /api/agent/runs
```

现在返回：

```text
HTTP 202 Accepted
```

原因是创建 Agent Run 只表示任务已经被接受，不代表 Agent 已经执行完成。

响应体仍然使用：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "run_id": "...",
    "status": "CREATED"
  }
}
```

其他查询接口暂时保持 HTTP 200。
