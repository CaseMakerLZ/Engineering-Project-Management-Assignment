## 2. 当前整体架构

```text
Frontend（待开发）
        ↓
Java Spring Boot
  ├── AgentServiceController
  ├── AgentService
  ├── PythonAgentClient
  └── GlobalExceptionHandler
        ↓ HTTP / JSON
Python FastAPI Agent Service
  ├── API
  ├── RunService
  ├── SQLite Repository
  └── AgentRuntime Adapter
        ↓
Python Agent Core
  ├── AgentLoop
  ├── AgentState / AgentMessage
  ├── LLMClient
  ├── ToolRegistry
  └── ToolExecutor
```

Java 与 Python 之间通过稳定的 HTTP/JSON 契约通信。Java 不依赖 OpenAI SDK 或 Python 内部对象；Python Agent Core 也不依赖 Spring Boot。

### 3.3 HTTP 状态码和业务码

响应体统一为：

```json
{
  "code": 0,
  "msg": "success",
  "data": {}
}
```

HTTP 状态码负责协议语义，业务码负责项目内部错误分类。

当前主要业务码：

| 业务码 | HTTP | 含义 |
|---:|---:|---|
| `0` | 2xx | 成功 |
| `10001` | 400 | 参数不合法 |
| `30001` | 404 | Agent Run 不存在 |
| `30002` | 409 | Run 状态冲突 |
| `40001` | 503 | Python Agent Service 不可用 |
| `40002` | 504 | Python 调用超时 |
| `40003` | 502 | Java/Python 内部鉴权失败 |
| `40004` | 502 | Python 返回异常或无法解析 |
| `90001` | 500 | Java 内部系统错误 |

### 3.4 异常传播链路

```text
Python HTTP / 网络异常
        ↓
PythonAgentClient 转换
        ↓
BaseException + ErrorCode
        ↓
GlobalExceptionHandler
        ↓
HTTP 状态 + Result 业务码
```

已覆盖：

- 连接失败；
- 连接/读取超时；
- 下游 401/403/404/409/422/503；
- 非法 JSON；
- DTO 参数校验；
- 未知 Java 异常。

### 3.5 XSS 告警处理

创建任务接口明确声明：

```text
Content-Type: application/json
Accept/Response: application/json
```

固定的 HTTP 202 使用 `@ResponseStatus(HttpStatus.ACCEPTED)` 表达，不再把响应交给通用 `ResponseEntity.body()` sink。测试确认恶意 `prompt` 不会被创建任务响应回显。

## 5. 当前已知问题

### 5.1 FastAPI BackgroundTasks 不可靠

Python 任务仍运行在 Web 进程内，进程退出时任务可能丢失。适合 MVP，不适合最终云任务系统。

### 5.2 SQLite 只适合第一版

多进程和并发写入能力有限。Java 的 MySQL 数据模型尚未建立，Python 后续也需要评估统一数据库或独立存储边界。

### 5.3 多轮会话与记忆尚未实现

当前支持单次 Run 内的 AgentLoop，不支持跨 Run 的 Session 对话，也没有 Project Memory 和 Context Management。

### 5.4 正式工具尚未装配

工具注册和执行基础设施已存在，但 Agent Service 默认 Runtime 还没有注册文件、代码搜索和测试等业务工具。

### 5.5 取消为软取消

取消会保护任务状态，但不能强制中断已发出的 LLM 请求或正在执行的外部工具。

### 5.6 生产级能力不足

尚缺：

- request ID 和链路追踪；
- 限流与 Agent 并发控制；
- 重试、熔断和幂等；
- 日志规范与敏感信息脱敏；
- 用户认证和资源归属；
- 数据库迁移；
- Docker 和云部署。

## 6. v1.0 建议范围

v1.0 应优先完成一个可部署的纵向闭环：

```text
用户注册/登录
    ↓
创建项目
    ↓
创建会话或 Agent 任务
    ↓
Java 调用 Python Agent
    ↓
查询状态、消息和结果
    ↓
用户只能访问自己的资源
    ↓
单机云部署
```

不应让 LangGraph、多 Agent、MCP、Skill 市场等扩展阻塞 v1.0。

## 9. 结论

项目已经从单机脚本原型进入了可由 Java 调用的双服务阶段。当前最重要的成果不是功能数量，而是建立了清晰边界：

```text
Java 负责网站业务、用户、项目、会话和权限；
Python 负责 Agent、LLM、工具、运行状态和记忆；
双方通过可测试的 HTTP/JSON 契约协作。
```

下一阶段应把重点放在用户业务闭环和可部署性上，同时保持 Agent Runtime 可替换，为后续 LangGraph、记忆系统和复杂工具链留出空间。
