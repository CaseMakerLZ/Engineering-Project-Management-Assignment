本地开发默认服务地址：

```text

Python Agent Service: http://127.0.0.1:8000
```

### Token 关系

```text
AGENT_SERVICE_INTERNAL_TOKEN
```

是 Java 和 Python 两端读取的环境变量名称。

```text
X-Service-Token
```

是 Java 调用 Python 时发送的 HTTP 请求头名称。

两端环境变量和请求头使用同一个实际密钥值：

```text
Python AGENT_SERVICE_INTERNAL_TOKEN
= Java AGENT_SERVICE_INTERNAL_TOKEN
= HTTP X-Service-Token
```

当前如果没有设置环境变量，Python 不启用内部 Token 校验，适合早期本地联调。

## 4. Java 调用 Python 的配置类

`Config.java` 创建了一个专门调用 Python Agent Service 的 `RestClient`：

```text
baseUrl = agent-service.base-url
```

当 `agent-service.internal-token` 非空时，会自动添加请求头：

```http
X-Service-Token: <token>
```

这样 Controller 不需要在每个请求中重复设置 Python 服务地址和 Token。

## 6. 今日修正的问题

### 6.1 查询任务没有传递路径变量

原实现只有 URI 模板：

```java
.uri("/api/internal/runs/{runId}")
```

现已改为：

```java
.uri("/api/internal/runs/{runId}", runId)
```

确保 `{runId}` 被实际任务 ID 替换。

### 6.2 创建任务使用了错误的响应类型

Python 创建任务返回：

```json
{
  "run_id": "...",
  "status": "CREATED"
}
```

原实现错误地使用 `CreateRunRequest` 接收响应。现已改为：

```java
CreateRunResponse
```

### 6.3 创建任务没有按照 JSON 请求体接收

现已使用：

```java
@Valid @RequestBody CreateRunRequest request
```

作用：

- `@RequestBody` 将前端 JSON 转换为 DTO；
- `@Valid` 执行 `@NotBlank`、`@Size` 等参数校验。

请求示例：

```json
{
  "project_id": "project-001",
  "prompt": "请分析当前项目"
}
```

### 6.4 补全查询消息接口

新增 Java DTO：

```text
MessageResponse
RunMessagesResponse
```

`MessageResponse.content` 暂时使用 `Object`，原因是 Python 消息内容可能是字符串，也可能是 JSON 对象。等消息领域模型稳定后，再替换成更明确的 Java 类型。

### 6.5 补全取消任务接口

新增 DTO：

```text
CancelRunResponse
```

响应包含：

```json
{
  "run_id": "...",
  "status": "CANCELLED"
}
```

## 7. Controller 异步问题结论

当前 `AgentServiceController` 使用同步阻塞的 `RestClient`，但整个 Agent 任务对用户而言仍然是异步任务模型。

流程：

```text
前端 POST /api/agent/runs
        ↓
Java 同步调用 Python 创建任务
        ↓
Python 保存 CREATED 并启动后台任务
        ↓
Python 立即返回 run_id
        ↓
Java 立即将 run_id 返回前端
        ↓
Agent 在 Python 后台继续运行
```

Java 请求线程只等待 Python 创建任务并返回 `run_id`，不会等待 LLM、工具和 AgentLoop 完整执行。

因此第一版采用：

```text
RestClient + Python 后台任务 + 前端轮询
```

是合理方案。暂时没有必要为了“异步”立即引入 WebFlux 或 `WebClient`。

前端第一版可以每隔 1～2 秒调用：

```text
GET /api/agent/runs/{runId}
```

后续再通过 SSE 改善实时输出体验。

## 8. Java 与 Python 的职责边界

`API_CONTRACT.md` 中的接口是：

```text
Java → Python Agent Service
```

的内部 Agent 执行接口，只负责：

- 创建 Agent Run；
- 查询 Run 状态；
- 查询运行消息；
- 取消 Run。

它们不负责网站业务中的：

- 用户注册登录；
- 项目管理；
- 会话管理；
- 对话消息管理；
- 权限控制。

未来完整架构：

```text
Frontend
   ↓
Java Public API
   ├── Auth
   ├── User
   ├── Project
   ├── Session
   ├── Conversation
   └── Task
            ↓ internal HTTP
       Python Agent API
            ├── Run
            ├── Agent Message
            ├── Agent Runtime
            └── Memory
```

## 9. 多轮对话现状

当前 Python Agent 支持：

```text
一次 Run 内的多步 AgentLoop 和工具调用
```

但不支持：

```text
多个用户回合之间的持续会话
```

未来需要引入三个主要标识：

```text
project_id
session_id
run_id
```

关系：

```text
Project
  └── Session
        ├── Run 1
        ├── Run 2
        └── Run 3
```

Java 负责保存用户、项目、Session、对话消息和业务任务；Python 负责根据 `project_id`、`session_id` 加载上下文、运行 Agent 并更新项目记忆。
