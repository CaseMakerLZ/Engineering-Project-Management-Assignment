# agent_service 当前架构

## 1. 唯一职责

`agent_service` 是 Python Agent 执行服务，给 Java Spring Boot 提供 HTTP 接口。它不负责项目、对话和用户业务。

```text
Java：Project / Conversation / AgentTask
Python：Agent Run / Agent Runtime / Agent Run Message
两端：通过 python_run_id 和 HTTP/JSON 连接
```

## 2. 当前核心模型

Python 只保留三类核心模型：

```text
RunStatus
    CREATED / RUNNING / COMPLETED / FAILED / CANCELLED

Run
    一次 Agent 执行任务，同时用于服务内部和查询接口返回

RunMessage
    一次 Run 内的执行消息，content 必须是 JSON 兼容值
```

不再额外维护 `RunRecord`、`RunResponse`、`MessageRecord`、`MessageResponse` 等重复模型。

## 3. 数据流程

```text
Java HTTP JSON
        ↓ FastAPI/Pydantic
CreateRunRequest
        ↓ RunService
Run(status=CREATED)
        ↓ MySQLRunRepository
agent_run
        ↓ BackgroundTasks
AgentRuntime
        ↓
Run(result, status, timestamps) + RunMessage[]
        ↓
agent_run / agent_run_message
        ↓ HTTP JSON
Java 查询结果
```

`Run.context` 只用于本次 Agent 推理，查询 Run 时不会返回；它不是 Python 的长期记忆。

## 4. MySQL 边界

Python 只创建和维护：

```text
agent_run
agent_run_message
```

Java 继续维护：

```text
project
conversation
agent_task
```

Python 不访问 Java 的业务表，Java 也不需要理解 Python Agent 内部对象。

## 5. HTTP 接口

```text
GET  /api/internal/health
POST /api/internal/runs                    → 202 + run_id/status
GET  /api/internal/runs/{run_id}           → Run
GET  /api/internal/runs/{run_id}/messages  → RunMessage[]
POST /api/internal/runs/{run_id}/cancel    → run_id/status
```

创建请求中的 `context` 是 Java 提供的历史对话文本：

```json
{
  "project_id": "project-001",
  "conversation_id": "conversation-001",
  "prompt": "继续分析",
  "context": [
    {"role": "user", "content": "上一轮问题"},
    {"role": "assistant", "content": "上一轮回答"}
  ]
}
```

## 6. 保存策略

保存任务级信息：

```text
run_id / project_id / conversation_id / prompt
status / result / error
created_at / started_at / finished_at
```

保存运行消息：

```text
sequence_no / message_type / content_json / created_at
```

OpenAI SDK 的 `Response`、`ResponseReasoningItem` 等对象只在 Agent Core 内部使用。运行时转换出的普通字典、字符串等 JSON 兼容值才允许写入 MySQL。

## 7. 当前保留的复杂度

`AgentRuntime` 协议和 `RunRepository` 协议仍然保留，因为它们是两个真实的替换边界：

```text
CurrentAgentRuntime → 未来 LangGraph Runtime
MySQLRunRepository  → 未来其他数据库实现
```

除此之外，本服务暂时不新增记忆模型、消息角色模型、错误 DTO 或额外状态枚举。

## 8. 当前限制

- 任务仍由 FastAPI `BackgroundTasks` 执行，进程退出可能丢失未完成任务。
- 运行消息目前在任务结束后批量保存。
- MySQL 表结构暂时由 Repository 启动时创建，后续应迁移到 Flyway/Liquibase 或独立 SQL 迁移。
- Python 与 Java 的业务写入仍不是分布式事务。
